# 三分钟录屏脚本

> 目标：满足赛题红线 —— **可验证的 PoC + 日志 + 视频**，不是 PPT。
> 每个镜头都标了「素材从哪来」，凡是标 ★ 的都能当场重跑。
> 最后更新：2026-08-12

---

## 〇、这三分钟要证明什么

**一句话**：这套系统的价值不在于不出错，在于**错误会以可判定的方式暴露**。

所以片子的主线不是「看，它跑通了」，而是：

> **我们凭什么说它是真的跑通了？**

这条主线有两个好处：一是它就是评委最想知道的；二是我们**手上恰好有它的证据**，
而多数参赛作品只有前半句。

★ **不要做的事**：不要演示「一句话生成完整应用」。我们没有 Planner，
一个需求现在只产出一个 packet。演示做不到的事，评委一追问就塌。

## 一、分镜（总长 3:00）

### 镜头 1 ｜ 0:00 – 0:20 ｜ 问题与主张

**画面**：桌面端首页（`packages/desktop/artifacts/screenshots/01-home.png` 或实机）

**口播**：
> 多 Agent 写代码，最难的不是让它们动起来，是**让它们出错时你能发现**。
> Codentum 的做法是：把可靠性交给六条不变量，由控制平面强制，
> 而不是靠提示词请求模型守规矩。
> 下面这三分钟，我们不演示它能做什么，演示**我们凭什么相信它**。

---

### 镜头 2 ｜ 0:20 – 1:00 ｜ ★ 真需求跑完整条链路（实机）

**画面**：录 `bash /d/tmp-codentum-dbg/run-diag.sh` 启动的应用

**操作**（需人点一下）：
1. 点「打开项目」→ 选演示项目（**必须是已有至少一个 commit 的 git 仓库**）
2. 输入需求（用规格写全的那条，见下方「附：演示需求原文」）
3. 点提交

**同时画面右侧或下方**：终端里的引擎日志（`.codentum/engine.log` 或 run-diag 输出）

**口播**：
> 需求从桌面端发出，经协议层进入控制平面，由真实模型执行。
> 这是阿里云百炼的 qwen-coder-plus，不是本地假数据 ——
> 右边是引擎日志，能看到 HTTP 请求和状态变更。

**要让观众看到的三个瞬间**：
- 状态从 `pending → running`（**说明中间态是真的落盘的**）
- 日志里那行 `HTTP Request: POST ... "HTTP/1.1 200 OK"`
- 状态到达终态

⚠️ 这一段是全片唯一依赖实时网络的部分。**试录时先跑通一次再正式录**；
若现场不稳，退回用 `docs/experiments/engine-live-run/` 的存档产物讲同样的事。

---

### 镜头 3 ｜ 1:00 – 1:50 ｜ ★★ 全片最重要的一段：系统不给自己签字

**这是我们与其他作品最不一样的地方，也是最该慢讲的 50 秒。**

**画面**：分屏 —— 左边模型的回复正文，右边 packet 的终态

**口播**：
> 看这次的结果：模型**没有报错**，它规规矩矩把代码写在了回复里。
> 但工作区里一个文件都没有被创建。
>
> 今天上午，这样一个 packet 会被判为 **accepted** —— 因为证据是真的，
> `result.json` 确实落了盘。
> 现在它停在 **review**，理由是：**「写了字」不等于「交了活」**。

**接着切到判据本身**（终端）：

```bash
python -m pytest packages/control-plane/tests/test_reconcile.py -q -k TouchedNothing
```

**口播**：
> 判据从「模型说了什么」换成了「工作区里多了什么」。
> 而这个数据一直都在 —— `touched_paths` 是冻结契约里的字段，
> worker 一直在上报，**只是控制平面从来没看过一眼**。
> 不是缺数据，是缺判定。

**最后一击**（可选，10 秒，效果极强）：现场把那段判定注释掉，重跑，测试变红。

> 我们判断一件事有没有做完的标准只有一条：
> **如果它坏了，哪条测试会变红？**

---

### 镜头 4 ｜ 1:50 – 2:35 ｜ ★ 对照数据：护栏关掉会怎样

**画面**：`docs/experiments/guardrail-ablation.svg`，逐行浮现下表

| 不变量 | 注入故障 | 护栏开 | 护栏关 |
|---|---:|---:|---:|
| I1 单写者（路径锁） | 8 | **0** | 8 |
| I5 单会话闭合（重试上限） | 8 | **0** | 8 |
| 全局预算上限 | 8 | **0** | 8 |
| I6 证据可判定（门禁层） | 32 | **0** | 32 |
| I1 并发压测（400 轮 × 5 线程） | 400 | **0 轮多赢家** | 315 轮，平均 2.688 个赢家 |

**口播**：
> 这不是模拟，是把注入了已知故障的 packet 分别在护栏开和关的情况下
> 跑完整的调和循环，数有多少被静默放行。
>
> ★ 关键在于：**「护栏关」不是我们造的对照组，那就是这个库的默认配置** ——
> 四个安全组件默认全是 None。**打开它们是产品入口做的选择。**

**诚实补一句**（15 秒，不要省）：
> 这张图不是进化增益曲线。我们的进化层还没实现，硬做只能编。
> 它证明的是「不变量确实在拦东西」，不证明「系统会自我进化」。

## 二、试录前的检查清单

**必须提前跑一遍，不要在正式录制时第一次跑：**

- [ ] 演示项目是 git 仓库且**至少有一个 commit**（否则 worker 会因
      `fatal: invalid reference: HEAD` 起不来）
- [ ] `DASHSCOPE_API_KEY` 已配（`run-diag.sh` 会自动读）
- [ ] 先用 `bash /d/tmp-codentum-dbg/run-diag.sh` 跑一次完整流程，确认引擎连上
- [ ] 清掉残留进程：`taskkill //F //IM python.exe //T`（★ 会杀掉所有 python）
- [ ] 演示项目的 `.codentum/` 建议**清空重来**，让第一帧是干净的起点
- [ ] 关掉可能弹窗的东西（微信、更新提示）
- [ ] 屏幕分辨率固定，字体调大到录制后可读

**已知需要人手动做的唯一一步**：点「打开项目」的原生文件夹对话框
（Electron 的系统级窗口，脚本驱动不了）。

## 三、附：演示需求原文

★ 用规格写全的这条，模型不会因为「上下文不足」而返回 blocker：

```
在 workspace/ 下新建 subscriptions.py。完整规格如下，不需要任何额外澄清：
(1) @dataclass class Subscription，三个字段 name: str、monthly_cny: float、renew_day: int；
(2) def monthly_total(subs) -> float，返回所有 monthly_cny 之和，空列表返回 0.0；
(3) 只写这一个文件，不写测试。
```

如果想演示**反面**（模型主动报 blocker、被系统 fail-closed 拦住），
就故意用一句含糊的需求，例如「做个日常规划的 APP」——
实测模型会返回 blocker 报告，packet 停在 review 且带
`sys:worker-failed:...:acceptance_not_met` 标记。

> ★ 这两条都值得录：一条证明**做得对时能走通**，
> 一条证明**做不了时会被拦住**。第二条其实更有说服力。

## 五、时间分配的理由

| 段落 | 时长 | 为什么给这么多 |
|---|---:|---|
| 真需求跑链路 | 40s | 必须有，但**它不是差异点** —— 谁都能演示「跑起来了」 |
| **系统不给自己签字** | **50s** | ★ 这是差异点。同一个输入、同一条链路，判据变了结果就变了，且有测试、有日志、有 git 记录 |
| 对照数据 | 45s | 把「可靠性来自不变量」从口号变成数字 |
| 工程门禁 | 15s | 证明前面所有数字不是手工凑的 |
| 开场 + 收尾 | 30s | |

★ 如果时间超了，**先砍镜头 2，不要砍镜头 3**。
「跑通了」是入场券，「凭什么信」才是分数。
