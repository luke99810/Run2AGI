## guardrail-ablation —— 护栏消融对照

### 它回答什么

Codentum 的中心主张是「可靠性来自不变量，不来自提示词」。
这句话要么是可测量的，要么是修辞。这个实验把它变成可测量的。

做法是消融（ablation）：把同一批**注入了已知故障**的 WorkPacket，
分别在「护栏开」与「护栏关」两种配置下跑完整的 `ReconcileLoop`，
数一数有多少故障被静默放行。

### 怎么重跑

```bash
python scripts/experiment_guardrails.py
```

零第三方依赖，`pip install` 之前就能跑。约 30 秒。
产出 `guardrail-ablation.json`（原始数据）与 `guardrail-ablation.svg`（图，自绘）。

### 结果（2026-08-10）

| 强制点 | 注入故障 | 护栏关 → 静默放行 | 护栏开 → 静默放行 |
|---|--:|--:|--:|
| I1 单写者（路径锁） | 8 | **8** | 0 |
| I5 单会话闭合（重试上限） | 8 | **8** | 0 |
| 全局预算上限 | 8 | **8** | 0 |
| I6 证据可判定（门禁层）† | 32 | **32** | 0 |

† 门禁那一组是「08-10 修复前 vs 修复后」，不是开关。见下方「实验第一次跑就抓到一个缺陷」。

**并发压测**（400 轮 × 5 线程抢同一路径）：

| | 出现多个赢家的轮数 | 平均赢家数 |
|---|--:|--:|
| 有互斥锁 | 0 / 400 | 1.000 |
| 去掉互斥锁 | **315 / 400** | **2.688** |

### ★ 关于对照组的两条说明（这部分比数字本身重要）

**1. 「护栏关」不是人造的稻草人。**

`ReconcileLoop` 的四个安全组件 —— `transition_table` / `gate_runner` /
`budget_tracker` / `guardian` —— **默认值全是 `None`**。
也就是说「护栏关」就是这套系统的默认配置，不是为了做实验特意拆掉的。
这一条本身就是结论的一部分：**护栏是可选的，那么默认就是关的。**

**2. 并发那一组的对照组保留了全部判定逻辑，只摘掉互斥锁。**

如果对照组用「根本没有锁」（申请永远成功），那每轮必然 5 个赢家 ——
等于把结论直接写进对照组，测不出任何东西。
所以对照组是 `_UnsynchronizedLockTable`：冲突检测一行不改，只去掉那把锁，
测的才是「并发下判定还成不成立」。

⚠️ 而且必须把 `sys.setswitchinterval` 压到 1µs。
08-03 第一次做这个实验时没压，**把锁整个删掉跑 400 轮依然每轮恰好一个赢家** ——
临界区太短，GIL 在 check-then-act 之间根本没机会切走。
详见 `docs/项目进展与记忆.md` §十五。

### ★ 实验第一次跑就抓到一个缺陷

搭这个实验时，为了给「门禁」这一轴设计注入故障，顺手对四个内置门禁取了一次样，
发现它们**全部放行**一个证据只有 `sys:lock:<pid>` 的 packet。

那条 `sys:lock:` 是 `_try_ready_to_running` 自己写的簿记 ——
正是 08-09 在兜底分支修掉的「系统自己给自己签字」。
兜底分支修好了，**门禁分支没修**，而门禁分支在 `_try_review_to_accepted` 里
**优先于**兜底分支。

结果是反直觉的：**配了 `gate_runner` 的系统比没配的更松。**
打开护栏这个动作，反而绕过了那次修复。

根因是同一个判据被写了两遍：`reconcile/loop.py` 里一份，
`gates/builtin.py` 里各写各的 `if not packet.evidence`。
修复把判据收进 `codentum_control_plane/evidence.py`，两边共用一份。

回归防线：`packages/control-plane/tests/test_gates.py::TestGatesRejectSysBookkeeping`
（把 `acceptance_evidence(...)` 换回 `packet.evidence`，它必须变红 —— 已验证）。

### 实验本身由测试守着

`tests/test_experiment_guardrails.py` 守三件事：

1. 护栏开的一侧必须**全拦住**——否则我们在拿一张「护栏也没用」的图去证明护栏有用
2. 护栏关的一侧必须**真的漏**——否则两侧一样高，图上没有任何信息，而它看起来仍然是一张图
3. 并发对照组不许退化成「根本没有锁」——那样每轮必然 5 个赢家

第 3 条最容易被无声破坏：把对照组换回「没有锁」，前两条**依然全绿**。

### 这份数据不证明什么

写清楚边界，比多列几个数字有用：

- **不证明进化有效。** P4/P5 尚未实现，这里没有任何「进化增益」的测量。
- **不证明模型能写对代码。** 全程没有模型参与，测的是控制平面的判定，不是产出质量。
- **不是性能数据。** 没有测吞吐、延迟、成本。
- **注入的是已知故障。** 它衡量的是「已知的坏情况会不会被拦住」，
  不是「系统能发现多少未知问题」。后者要靠证伪门与影子回放（P6），还没做。
