## 一、背景

第 0 周定技术栈时，模型接入写的是 `anthropic` SDK，经 `ModelGateway` 统一出口。
那时只考虑了工程因素，**没有把赛题生态算进去**。

对照 `工具下载与平台注册清单.md`（自大赛手册整理）后暴露两点：

1. 大赛由**阿里云主办**，赛道是「新智基座｜Agent Infra」，手册推荐
   **阿里云百炼（Qwen）** 作为 LLM Provider
2. **AgentTeams 安装时必须配置 LLM Provider 与 API Key** —— 而 AgentTeams
   是手册里唯一用「必须」措辞的硬要求（见 §11.1 技术栈总览）

一份在阿里云主办的赛道里、只调 Anthropic 的方案，需要一个说得过去的理由。
我们没有那个理由 —— 当初就不是权衡后的选择，是根本没考虑。

---

## 二、决策

**阿里云百炼（Qwen 系）为默认 Provider；Anthropic 保留为等价可切换实现。**

```
                    ModelGateway（已冻结的接口）
                            │
              ┌─────────────┴─────────────┐
              │                           │
      ★ 百炼实现（默认）            Anthropic 实现（备）
      compatible-mode              anthropic SDK
      赛题生态贴合                  对照 / 可迁移性演示
```

三点说明：

1. **不是「只用百炼」。** 保留第二实现有独立价值，见 §三
2. **切换是部署级配置，不是运行时策略。** 提示词缓存按模型分桶，运行中切
   Provider = 整个前缀冷重写（ADR 约束 2）。切换发生在启动配置，不在一次尝试内
3. **`ModelGateway` 签名一个字不改。** 它第 0 周已冻结，Provider 本来就是它
   后面的实现细节 —— 这次换 Provider 没有触发任何契约变更，恰好验证了那层
   抽象是有效的

## 三、为什么保留 Anthropic 而不是删掉

三条理由，第一条最重要：

### 3.1 把「可迁移性」从主张变成可演示动作

`00-总体设计方案` 里有一条从 DevPlex 吸收的机制 —— **等价契约切换开关**，
当初收进来的理由就是「把可迁移性变成可演示动作」。

**现在它有了真实的两端。** 现场切一次 Provider、两边都跑通同一个 packet，
比在 PPT 上写「我们做了供应商抽象」有说服力得多。

> ★ 三分钟录屏里，这是一个**看得见**的动作。而初赛红线正是
> 「仅 PPT / 概念方案、无可验证 PoC → 直接淘汰或大幅扣分」。

### 3.2 模型隔离（I 类硬约束）需要足够的异构性

`ModelGateway.open()` 强制校验 **coder ≠ reviewer、evolver ≠ verifier** ——
同一模型既写又审，盲区会在两处同时出现，评审就成了摆设。

⚠️ **待验证**：百炼上是否有足够异构的模型来满足这条隔离。百炼同时上架
Qwen / DeepSeek / Kimi / GLM 等多家，**理论上够**，但没实测。
若不够，第二 Provider 就从「演示用」变成「隔离所必需」。

### 3.3 对照组

Qwen 在 Coder / Reviewer 角色上的实际表现**我们没有任何数据**。
留一个已知基线，出问题时能区分「是模型不行」还是「是我们的 Harness 不行」。

## 五、🔴 遗留冲突：冻结的契约把币种写死成了美元

`interfaces.py`（第 0 周冻结）里，成本字段**全部以 usd 命名**：

```python
BudgetGrantRuntime.limit_usd: float
WorkerCompleted.spent_usd / WorkerFailed.spent_usd / WorkerAborted.spent_usd
Usage.cost_usd          # "预算判断一律看 cost_usd"
ModelGateway.open(..., grant_usd: float)
```

**而阿里云百炼以人民币计价。**

### 为什么这条必须现在提出来，而不是「实现时再说」

设计里「预算一律用货币，不用 token」这条，理由写得很清楚：

> 不同模型家族的分词器差异可达 ~30%，异构路由下按 token 记预算会**静默失真**，
> 且失真方向随路由变化，事后查不出来。

**一个写死的汇率会把同一类失真原样请回来。** 汇率变动不会报错，只会让账本
慢慢偏离，而偏离方向随汇率走 —— 和 token 口径的病症一模一样。用货币替代
token 是为了消灭这类静默失真，如果转头在货币里再塞一个硬编码汇率，
那这条设计约束就自我抵消了。

> ★ 这不是假想风险。同一天在另一个项目里刚踩过一次：一段
> 「按 ¥7/USD 从美元价换算」的定价代码，从引入那天起就偏了 1.5~2%，
> 偏了一个月没人发现 —— 因为它不报错。而那还是有官方人民币公布价可查的情况。

### 三个可选解，各有代价

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 汇率转换** | 网关边界处 CNY→USD | ❌ 正是上面那个坑。若非要走，汇率**必须记进证据包**，让它可审计而不是隐形 |
| **B. 改契约为币种标注** | `Money{amount, currency}` 或改名 `limit_cny` | 契约变更 —— 需三人同意 + ADR + 变更窗口。**但这正是那个流程存在的理由** |
| **C. 认定 usd 是「记账单位」** | 名字不动，语义改为「以某个基准货币计的抽象额度」 | 最省事，但**名字与实际含义不符**，正是这套设计最反对的那种漂移 |

### 本 ADR 的立场

**倾向 B，但不在本 ADR 里单方面执行。**

理由：契约冻结（I3）的规矩是「只有 A 能写 contracts，且改动需三人同意 +
新 ADR + 走变更窗口」。A 一个人以「反正我是 owner」为由绕过自己定的流程，
比那个字段名错了更糟 —— **我们整套论点建立在「约定靠不住，约束才可靠」上，
第一次遇到不便就自己松一次，之后这条约束对谁都不再成立。**

**行动项**：由 A 发起一次 ContractChangeRequest，三人确认后落 ADR-0006。
在那之前 **Provider 决策照常生效**，两者不互相阻塞 —— 币种口径影响的是
预算账本的准确度，不影响能不能调通模型。

## 七、被否决的两个选项

| 选项 | 否决理由 |
|---|---|
| **只用百炼，删掉 Anthropic** | 失去 §3.1 的可演示切换动作；且在 Qwen 表现完全没实测的情况下，删掉唯一基线等于把风险全押在一个未验证项上 |
| **维持只用 Anthropic** | 在阿里云主办的赛道里说不过去，且与 AgentTeams 安装要求配置 Provider 这条事实不匹配。**当初这不是权衡后的选择，是没考虑** —— 这类「默认值伪装成决策」的地方，发现一处就要改一处 |
