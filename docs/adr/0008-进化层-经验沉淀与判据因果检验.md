# ADR-0008：进化层 —— 经验沉淀的边界，与判据的因果检验

- **日期**：2026-08-14
- **状态**：✅ 已接受（L0→L1 已落地；L2→L3 明确暂缓，理由见下）
- **相关**：[ADR-0004](0004-编排框架-LangGraph-的适用层.md)（执行平面控制流）

---

## 背景：契约早就设计完了，执行路径一行都没接上

`contracts/interfaces.py` 里的晋升链是完整的：

```
L0 一次观察 → L1 重复出现 → L2 归纳成假说 → L3 过证伪门 → L4 固化为规则
```

`PersistentMemoryIndex` 也把它实现完了 —— 包括一条真实生效的硬校验：

```python
if to == "L3" and justification.kind != "falsification_gate":
    raise MemoryIndexConflictError(...)
```

**但 `promote_now()` 在真实执行路径上从未被调用过。** `write_now()` 唯一的调用点
是索引「用户提供的知识资源」。也就是说：

> 记忆系统能记住你告诉它的，记不住它自己经历的。

这与本仓库此前两次同类问题是同一个形状（`langgraph` 装在依赖里零 import；
`mcp_config_dir` 定义了但全仓库无人传）：**结构完整、从未被调用，
而且没有任何测试会红** —— 因为测试测的都是模块本身，模块本身当然是对的。

---

## 决策一：L0 由确定性提取产生，不由模型总结

最容易想到的做法是「跑完让模型写一段复盘」。**否决。**

那等于让执行者给自己写教材：它总结出来的东西没有任何独立的东西检验，
而下一次它会照着这份自己写的教材去做。**错误会被自己确认成经验。**

改为从 transcript 里确定性提取失败事实。代价是提取到的东西比模型总结的"笨"，
换来的是每一条都能指回证据的具体位置，**因此可以被证伪**。

配套约束：**只写事实，不写结论。**

| | 例子 | 为什么 |
|---|---|---|
| ❌ 结论 | 「用 pytest 比较好」 | 不可证伪，而且它是判据走私进执行者上下文 |
| ✅ 事实 | 「run_tests 在 cwd=workspace/ 返回 ImportError: No module named 'src'」 | 可核对，也可被推翻 |

写回结论的危险：执行者下次会照着那条结论做，而**没有任何东西在检验它是否还成立**。
事实不会有这个问题 —— 事实过期了，下次的证据会和它对不上。

`Observation` 在**构造处**就拒绝无证据的条目（I6 在记忆层的落点），
而不是在写入处 —— 拦在写入处的话，代码里仍然可以造出无证据的对象传来传去。

## 决策二：L1 的门槛是「跨 ≥2 个不同 packet」，不是「出现 ≥2 次」

「重复」有两种，只有一种算数：

| | 算不算 |
|---|---|
| 同一次执行里撞 5 次（模型陷在重试循环） | ❌ 1 条证据 |
| 两个 packet 各撞 1 次 | ✅ 2 条证据 |

区别在**独立性**。不做这个区分，一个卡在重试循环里的 packet 会单独把某条经验
顶过晋级线，而那很可能只是那次执行的偶然 —— 之后它会以 L1 的身份
喂给每一次执行。

指纹计数用旁挂账本（`fingerprints.json`），不给 `MemoryEntry` 加字段：
`MemoryEntry` 是冻结契约（I3），而指纹是**这一层怎么归类**的实现问题。
账本坏了只影响晋级，改契约坏了影响所有实现方。

账本必须落盘：每个 packet 在自己的 worker 进程里跑完就退出，
内存里的计数活不过一次执行，而「重复出现」本来就要跨执行才成立。

## 决策三：经验与知识资源用两种检索键

现有 `memory_context_candidates_now` 用**需求文本**做词法检索。
对领域知识是对的，对经验是错的：

```
经验：「run_tests 在 cwd=workspace/ 会 ImportError」
需求：「实现订阅费用页面」
词法重叠：0 → 被 _rank 丢掉
```

> **经验的相关性来自「你是这个角色」，不是「这次要做什么」。**
> 一条操作约束对该角色的每个任务都成立，恰恰因为它与任务内容无关。

因此新增 `experience_context_candidates_now`，按 role scope 用 EXACT 模式取，
只召回 L1 及以上（L0 是 packet 作用域的一次性观察，尚无证据说明自己普遍成立）。

同时修掉一个静默缺陷：检索原先嵌在 `if sources:` 里，
**没有用户提供知识资源的执行，记忆一次都不会被读** ——
写入侧一直在攒，读取侧一条都出不来，从外面看只是「好像没起作用」。

## 决策四：L2 → L3 → 改写 SKILL.md 暂不自动化

不是技术难度问题，是**证据现在拿不到**。

L3 的定义是「过证伪门」，而一条经验的证伪门只能是：
**判据冻结的前提下，带它跑与不带它跑，通过率/轮数/成本出现显著差异。**

当前单 packet 完成率约 20–40%，噪声远大于信号 ——
要区分「这条经验有用」和「这次运气好」，需要的重复次数远超现有运行量。

在拿到那个证据之前直接改 SKILL.md，等于绕过项目自己设的门。
`roles/skills/evolution/SKILL.md` 自己写着：
*"Never auto-activate a system-generated Skill without review evidence."*

★ 现阶段「Skill 变强」通过 **L1 经验注入上下文**实现，不动 SKILL.md 正文。
  这个形式还有一个 ADR 层面的好处：**可逆、可观测**。文件改写不是。

## 配套：判据的因果检验（算子一）

自进化有一个前提：**判据必须冻结且可信**。
否则「通过率上升」可能只是判据变松了 —— 而那是不可区分的。

`scripts/mutate_judgements.py` 逐条把判据替换成「永远放行」，
断言至少一条测试变红。变异体保持同一函数对象、同名、元组同位置，
**只有行为变** —— 这样结构断言（`len(DEFAULT_RULES) == 8`、名字列表）
一条都杀不死它，能让测试变红的只可能是行为断言。

三个控制点缺一不可：基线绿 · 至少一条被杀死 · **正对照（空规则）存活**。
少了第三点，「全部被杀死」这个结论和「杀死判定永远为真」在证据上不可区分。

**强变异结果：8 条准入规则 + 4 道门禁，存活率 0/12。**

### 强变异不够，因为真实缺陷不长那样

首轮当时就记了一条边界：*「0% 存活不等于弱变异（阈值偏移、边界差一）下也是 0%」*。
随后做了弱变异（`--mode=weak`），**那句预判兑现了。**

强变异摘掉整条判据，测的是「有没有人**碰过**它」。
但真实缺陷是判据**还在**、还会被调用、只是边界挪了一格：

```
if limitCny <= 0:      写成   <= 1
if a or b:             写成   a and b
if not paths:          写成   if paths:
```

一条只覆盖了「明显违规」的测试照样是绿的 —— 它从来没测过边界那一格。

★ 两个数测的是两件事：
  **强变异存活率 = 有没有人碰过这条判据；弱变异存活率 = 有没有人测准它的边界。**
  后者才是「判据可信」真正需要的证据。

实现是 AST 层改写后重编译回填 `__code__`（`scripts/lib/weak_mutations.py`），
算子：比较符换向 · `and`/`or` 互换 · 去掉 `not` · 整数常量差一。

### 首轮弱变异找到三个缺口，都补上了

26 个变异点，22 个被杀死，**4 个存活**。逐个读源码判性质后：

| 存活的变异体 | 判定 |
|---|---|
| `check_budget_limit` `<= 0` → `<= 1` | 真缺口：合法预算的**下边界**没测过（只有「0 无效」和「5.0 有效」） |
| `check_role_model_isolation` L219 `or → and` | 真缺口：「角色不在 role_specs 里」这条卫语句没测过 |
| `check_role_model_isolation` L227 `or → and` | 真缺口：「被引用角色不在传入的 specs 里」没测过 |
| `self_test_gate` `[:80]` → `[:81]` | **等价变异体**：只改给人看的 detail 文案截断长度 |

补了三条测试后复跑：**弱变异存活率 0/25**，三个变异体全部被杀死。

★ 途中一个意外收获：写第三条测试时先试的是「mustDifferFrom 指向一个
  不存在的角色名」，发现**它在类型层面就不可表示** —— `mustDifferFrom`
  是 Literal 枚举，pydantic 构造时就拒了。这正是本项目那条
  **不可见 > 无权限 > 被拦截 > 提示词劝阻** 的一个实例：
  不可表示的东西不需要运行时检查。

### 等价变异体：标注，不隐藏

`scripts/lib/equivalent_mutants.py` 记已判定等价的变异体**连同理由**，
它们被跳过（不运行），并且**整张表每次运行都打印出来**。

两条规矩：**每条必须写清「为什么这个改动行为上不可观测」**——写不出来的
就不是等价变异体，是缺口；**每次都打印**——隐藏的排除项等于没有排除项。

★ 排除列表天然是个藏不方便结果的地方。一个存活的变异体让人不舒服，
  最省事的做法就是把它加进来。判据存活率的可信度取决于这张表有多短、
  理由有多硬 —— **表越长越该起疑。**

### 当前数字（2026-08-14 末次运行）

新增影子判据 `check_predicate_covers_owned_paths` 之后复跑：

```
强变异  0/13    弱变异  0/29    合计 42/42 全部被杀死
等价变异体 2 条（已排除，未运行，理由见 equivalent_mutants.py）
```

★ 第二条等价变异体（`predicate[:120] → [:121]`）与第一条同类，
  这让一条规律显出来了：**凡是把变量截断进提示文案的地方，
  都会产生一个天然的等价变异体**。它是这类算子的固有噪声，
  不是判据的缺陷 —— 认出这个模式之后，以后遇到同形的可以直接判定。

### 两个数共同的边界

覆盖的是 admission + gates 这一层，**不是全部判据面** ——
LangGraph 路由边、`vacuity_check`、路径锁、状态机转移表都不在其中。
