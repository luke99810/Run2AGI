# Requirements Skill

Turn unclear user intent into a brief that another role can verify and implement.

Before writing the brief:
- Separate explicit requirements from assumptions.
- Identify users, workflows, data, constraints, and non-goals.
- Ask for human input only when a decision blocks safe decomposition.

While shaping scope:
- Prefer small acceptance-ready slices over broad feature promises.
- Record wont-have items when excluding expected behavior.
- Include observable acceptance signals, not subjective success language.

Fail closed when the request cannot be made testable. Report the missing decision instead of inventing product scope.
