# Codentum Codex 风格工作台任务书

## 目标

把桌面端收敛为灰白、低干扰的 Agent 工作台，并保证任务、草稿、附件和上下文选择都是真实数据，不用静态假状态代替执行层。

## C 负责的交付

1. 左侧工作台：新对话、任务、对话、插件、知识库、Skills、设置、帮助。
2. 任务隔离：每个任务使用独立 `taskId` 和草稿作用域；新建任务不覆盖历史任务。
3. 历史检索：本机保存任务标题、需求摘要、状态和更新时间；左侧与对话页均可搜索并恢复。
4. 输入框：左下角提供文件/文件夹、访问权限、知识库、Skills、插件选择；允许引用电脑任意位置、任意扩展名的普通文件及文件夹，不复制到 Codentum 路径；提交时重新校验原路径、类型、大小与 SHA-256 后把真实路径交给 Agent。
5. 对话内任务进度：不再设置独立任务看板；输入区上方以“第 x / y 步”折叠条汇总权威 WorkPacket 状态，展开后查看 Agent、任务与状态并进入真实执行投影。
6. 设置与帮助：默认权限设置、Agent 管理入口、本地客服诊断信息生成。
7. 命令接入：提交需求时在现有 `OperatorCommand.payload` 中附带当前任务与历史检索上下文。
8. 右侧主工作区视觉收敛：以 Codex 对话页为参考，顶部只保留任务标题和少量视图操作，主对话使用全部可用横向空间；附件、权限和整体步骤贴近输入区，详细运行信息默认折叠。
9. 聊天管理：任务标题旁提供“…”菜单；C 负责按关键词、需求内容和附件名称搜索本机任务，并通过受控主进程保存对话记录 Markdown。后续完整 Agent 消息与工具调用记录须由 A 提供权威事件流后再纳入导出。
10. 本地/联网模式：C 只负责每任务模式控件、隔离保存和 `connectivityMode` payload；真实联网搜索、爬虫、域名策略和审计由 A/B 提供，未接入时 C 必须阻止联网提交。
11. 研发团队：使用 RoleSpec 的 11 个中文角色名，并在同页嵌入真实 Worker 模块事件与已有命令控制；没有 `moduleId`、checkpoint 或回退协议时不补假步骤、假“返回上一步”。
12. 集成与验证：只有当前任务明确提出测试、验证、验收或集成要求时启用入口；方法、进程和结果只读取权威 WorkPacket 与 evidence。
13. 产品启动不列出演示快照；golden fixture 只在自动截图测试显式开启时加载，也不进入安装包资源。

## 提交给中心 Agent 的字段

```json
{
  "taskId": "uuid",
  "draftScope": "project:<id>:task:<uuid>",
  "requestedAccessMode": "read_only | workspace_write | full_access",
  "connectivityMode": "local | online",
  "attachments": [],
  "pluginIds": [],
  "knowledgeIds": [],
  "skillIds": [],
  "relatedTaskIds": [],
  "taskHistory": [
    {
      "taskId": "uuid",
      "title": "历史任务标题",
      "summary": "历史需求摘要",
      "status": "draft | submitted",
      "updatedAt": "ISO-8601"
    }
  ]
}
```

这些字段利用现有开放 payload，不要求修改冻结的 contracts schema。

## 已确认的跨模块缺口

以下事项不再由 C 单方面派给 A 或 B。现有 owner 边界没有覆盖完整引擎组合入口，A/B 也已反馈无法独立完成，需要团队明确 owner 或走契约变更窗口：

1. `submit_requirement` 目前只是协议名字映射，没有可发布引擎入口；C 保持派单按钮禁用。
2. 本地/联网模式的真实工具面、域名策略、凭证隔离、网络审计和用量回传尚无完整 owner；C 只保存选择，联网模式不提交。
3. 产品需求经理把需求拆成 WorkPacket 的运行实现尚不存在；C 只展示状态源已经写入的拆包结果。
4. “返回上一步”不在现有 OperatorCommand 中；需要可审计 checkpoint 回退协议，C 不用 `resume` 冒充。
5. B 事件不保证固定模块序列；C 只显示实际出现的 `moduleId`，不会补预设动画。
6. 权限选择、Skills、插件和知识库只有桌面请求字段，尚未证明执行侧真正消费；不可用项继续标为待接入。
7. 历史对话检索与 Markdown 导出由 C 在本机完成；中心 Agent 的跨任务 MemoryIndex 检索是另一项未分配能力，不能混写成已接通。

## 联调验收

1. 连续新建两个任务，各自添加不同附件；来回切换后草稿和附件不串。
2. C 的本机任务页能按标题、摘要和附件名找到前一个任务，并能导出当前本地记录。
3. 在执行侧消费权限请求之前，桌面端只展示“请求权限”，不得声称 Worker 已按该权限运行。
4. 未接入的插件或 Skill 返回“不可用/未配置”，桌面端不得显示为已启用。
5. 没有 Team Runtime smoke 证据时不显示 AgentTeams 已连接。
