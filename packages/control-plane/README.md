# control-plane —— 控制平面

> ★ **这个 package 里不允许出现任何模型调用。** 一行都不行。

---

## 职责

**做什么**：决定"下一步做什么、谁能做、能不能过"。调度循环、状态机、路径锁、准入校验、门禁、预算、Guardian。

**明确不做什么**：
- ✗ 不执行任务（那是 harness 的事）
- ✗ 不调用 LLM
- ✗ 不知道任务内容是什么（它只看 WorkPacket 的元数据，不看代码）

**为什么零 LLM**：风险分配原则——**不可恢复的错误交给确定性代码，可恢复的错误才交给模型**。锁判错就是数据损坏，没有重试能救回来；而代码写错了，测试会打回来重写。

## 依赖

**依赖**：`contracts` （仅此一个）

**⚠️ 不依赖 `harness`。** 控制平面必须能在没有执行体的情况下推进状态、跑完整测试。这一条被打破的信号很明显：你在 `control-plane/` 里 import 了 `harness/` 的东西。停下来。

**被依赖**：`desktop` 只读它产出的状态文件，不 import 它的代码。

## 目录

| 目录 | 职责 | 关键约束 |
|---|---|---|
| `reconcile/` | 调和循环：读期望状态 → 比对实际状态 → 产出动作 | 幂等。同一状态跑两次结果相同 |
| `state-machine/` | WorkPacket 的状态转换 | 转换表从 RoleSpec 派生，不手写 |
| `locks/` | 路径锁（前缀树）+ 乐观锁提交 | ★ I1 单写者的实现。**判错即数据损坏** |
| `admission/` | 准入校验器：动作合不合法 | 拒绝在前，执行在后 |
| `gates/` | 门禁：绿线、验收谓词判定、集成闸 | 判定必须可复算 |
| `budget/` | 预算记账与降级链 | ★ 货币计，不用 token |
| `guardian/` | 确定性拦截器 | ★ 无 LLM。拦截率要回流到进化层 |

### 与 Kubernetes 的同构

不是比喻，是精确对应——照着 K8s 的成熟结构想，出错概率低得多：

| Codentum | Kubernetes |
|---|---|
| `.codentum/` 状态文件 | etcd |
| `reconcile/` | controller manager |
| WorkPacket | Pod spec |
| `admission/` | admission controller |
| `gates/` | rollout gate |

## 完成定义

```
□ 调和循环幂等：同一状态输入跑两次，输出动作序列完全相同
□ 路径锁：并发申请重叠路径时，有且只有一个成功（写并发测试证明）
□ 准入校验：六条不变量各有对应的拒绝用例，且都能拒
□ ★ 全程零模型调用：grep 全目录无任何模型 SDK 的 import
□ 能在无 harness 的情况下用 mock WorkerRuntime 跑通完整调度
```

---

## 硬约束

1. **零 LLM。** 见上，不重复。
2. **调和循环必须幂等。** 不幂等就没法崩溃恢复，而崩溃恢复是本地桌面软件的刚需（用户会关电脑）。
3. **锁的判定不许"大概率正确"。** 有疑问就拒绝——拒绝的代价是一次重试，判错的代价是数据损坏。
4. **拒绝要给出机器可读的理由码**，让 harness 能据此决定重试还是升级求助，而不是靠解析文本。
5. **Guardian 的拦截记录必须落盘。** 拦截率是进化层的输入信号之一——不落盘，进化层就瞎了一只眼。
